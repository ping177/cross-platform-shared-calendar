# v0.1.19 — Task Due-date Push Reminder

Approved implementation scope: four bounded tasks, based on the repo-first gate at
`34e52dfb94bdb7b2ca355a4ad2d00a8deb32618c`. Local implementation/testing only;
Production SQL/Edge rollout and push require separate authorization.

## Contract

- One nullable Task-level reminder: off / same civil day 08:00 / prior civil day 20:00.
- No due date means no reminder. New UI-created Task with due defaults to 08:00;
  historical Tasks stay off and have no guessed timezone, including ordinary edits.
- Enabling requires valid captured IANA timezone. Preserve canonical timezone on later
  device changes; no UTC fallback. Date conversion uses existing shared DST primitives.
- Personal recipient is the Personal Space owner; Shared assigned recipient is current
  assignee; Shared unassigned recipients are all current Space members, each active device.
- Server marker changes on due/preset/timezone/status/assignee only. Cosmetic title
  edits preserve it. Completion/reopen and FK assignee set-null invalidate snapshots.
- Discovery is a hint. Service-only claim and pre-send canonical checks authorize send.
  Due must not precede marker and must fall in the existing inclusive ten-minute grace.
- Existing ledger, single minute scheduler, workers, Web Push, finalize and no-retry
  behavior remain. No hidden Event, Task occurrence table, queue or generic framework.
- Pre-send check is the final database qualification point; changes after its transaction
  and provider acceptance cannot be atomically canceled or retract notifications.
- Existing 50-task selection overflow can remain blocked by already-claimed identities;
  no throughput correction is included in this version.

## Implementation and verification

1. Persistence/invalidation: Task three fields and server trigger, historical compatibility.
2. Ledger/backend: task_id, three-source XOR, civil due identity, candidate/claim/check;
   Tasks toggle joins existing Space locking, direct Task CRUD stays.
3. Existing sender: one explicit Task branch, recipient resolution and namespaced tag.
4. Existing TaskSheet: three presets, new-only default, capture and canonical reread.
